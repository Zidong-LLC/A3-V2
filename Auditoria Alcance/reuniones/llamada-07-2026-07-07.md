- A3 plantea integración con ubicación de Google. Actualmente los mensajeros pueden compartir ubicación en Google; la idea sería centralizar esa ubicación en la plataforma.
- Se aclara que esto no estaba en el alcance inicial. Speaker G pregunta si estaba en el alcance inicial y luego señala que deberían cerrar el proyecto base para no seguir agregando indefinidamente nuevas cosas.
- **Criterio acordado: dejar GPS como punto de mejora/evolución posterior, no como bloqueo del cierre actual.**
- A3 aclara que ya no usan empresa externa de GPS, sino Google, porque les funcionó mejor.

## 9. Módulo de muestras
- La plataforma muestra análisis/muestras cargadas y en qué etapa está cada pedido.
- Permite ver pedidos pendientes de recoger y cuántos pedidos están en cada fase.
- Incluye catálogo de análisis cargados y perfiles personalizados creados por clientes.

## 10. Portal del cliente final
- Se muestra una versión simple del portal del cliente.
- El cliente puede solicitar análisis, ver resultados, recibir notificaciones por WhatsApp y, cuando el análisis esté listo, pedir o descargar el documento.

## 11. Prueba colectiva de trazabilidad
- A3 propone hacer una prueba colectiva completa: simular una solicitud real desde cero hasta cierre.
- La prueba debía incluir: cliente/veterinaria; orden de servicio; forma de pago; mensajero asignado; trazabilidad interna; eventual factura.
- A3 pide que Luciano vaya guiando el proceso paso a paso.

## 12. Problema de reinicio / pruebas desde cero
- Para hacer pruebas limpias, hay que reiniciar historial/contexto.
- A3 señala que eso mismo les pasa cuando quieren probar: no saben bien cómo iniciar desde cero.
- Pedido: dejar una forma más clara de reiniciar, finalizar o empezar una prueba limpia.

## 13. Menú inicial según tipo de cliente
- Si es primera interacción, el bot muestra menú con opciones 1, 2, 3 y 4.
- Si el usuario ya está registrado, no debería repetir todo el menú.
- Para cliente registrado, debería saludar y preguntar qué necesita.

## 14. Búsqueda por palabra clave: ejemplo "Planet"
- Se prueba búsqueda con "Planet". El bot muestra varias opciones como Animal Planet / Tercer Planeta.
- El usuario elige una opción y confirma que es correcta.
- Este comportamiento parece ir en línea con el pedido de búsqueda por coincidencias.

## 15. Captura de orden de servicio
- Se ingresan datos de orden durante la prueba: médico Sergio Pepito; especie/animal especial; raza Holstein; edad 9 años; propietario Matías; sin observaciones; análisis cardiovascular / cuadro hemático / sodio / potasio.
- Problema detectado: algunos datos no se muestran o capturan como A3 espera.
- Pedido: seguir puliendo la experiencia del cliente en el chatbot.

## 16. Cambio de cliente durante la orden
- Se debate si debe permitirse cambiar el cliente una vez seleccionado.
- **A3 concluye que no debería permitirse cambiar el cliente maestro.**
- Sí se debería poder cambiar dirección.
- Sí se debería poder cambiar análisis.
- Si el cliente está mal seleccionado, lo correcto sería anular/cancelar y empezar de nuevo.
- A3 argumenta que permitir cambiar cliente abre riesgos, porque el cliente maestro es la base de todo el historial y de la identificación.

## 17. Reconocimiento futuro por teléfono
- Se vuelve a mencionar que, en el uso real, el teléfono debería reconocer al cliente.
- Si el número ya está asociado a un cliente, el bot debería saludar y operar sobre ese cliente.
- Ese cliente maestro no debería poder cambiarse desde la conversación.
- Puede permitir cambiar dirección o datos de la orden, pero no la identidad base del cliente.

## 18. Varias órdenes para un mismo cliente
- A3 pide finalizar una orden y agregar otra para el mismo cliente.
- Se recuerda que una recogida puede contener varias órdenes.
- El bot debe permitir agregar otra orden de servicio para el mismo cliente sin reiniciar todo.

## 19. Problemas con perfiles/análisis
- Se prueban perfiles como "prequirúrgico 2", "parasitológico 3" y "prequirúrgico 1".
- Problema: el bot agrega una prueba que no corresponde o se queda atascado.
- También se detecta que "prequirúrgico 1" no fue tomado correctamente en pruebas previas de A3.
- Pendiente: revisar matching semántico de perfiles/análisis para que no confunda nombres ni números.

## 20. Especies grandes y especies no contempladas
- Durante la prueba aparece el caso de toro/bovino. El sistema presentó problemas porque "toro" fue tomado como especie.
- A3 aclara que toro no es especie; la especie correcta es bovino. Toro hace referencia al macho.
- A3 aclara que trabajan también con especies grandes: equinos, bovinos, porcinos, caprinos.
- También trabajan con perros, gatos, conejos, aves, silvestres y roedores.
- Pendiente: A3 debe enviar listado completo de especies y razas para validar correctamente.

## 21. Necesidad de validar especie y raza
- Si el usuario pone una raza en el campo especie, el sistema debe detectarlo.
- Ejemplos: persa no es especie, es raza; San Bernardo no es especie, es raza; toro no es especie, corresponde a bovino.
- Pedido: cargar listas de especies y razas para que el bot pueda validar mejor.

## 22. Datos del médico veterinario
- Debe validarse mejor el médico solicitante.
- No debe quedar simplemente "Doctor Matías" o "Sergio".
- Debe quedar nombre completo.
- Idealmente debe incluir apellido e identificación / tarjeta profesional.
- A3 puede enviar base de médicos asociados a clínicas.
- La validación debe confirmar que ese médico está autorizado para solicitar órdenes por esa clínica.

## 23. Bases de datos que A3 debe enviar
- Base actualizada de clínicas/clientes.
- Base de médicos asociados a clínicas.
- Tarjetas profesionales / identificaciones de médicos.
- Base de especies.
- Base de razas por especie.
- Clientes nuevos a la fecha.

## 24. Formato de precios
- Problema detectado: algunos precios aparecen como "18K".
- A3 pide que aparezcan en formato colombiano completo: mostrar "18.000" en vez de "18K".
- Esto aplica especialmente al resumen de exámenes de unidad. En perfiles está bien.

## 25. Experiencia del cliente en el chatbot

- No lograron cerrar la orden completa durante la llamada por fallas técnicas y casos no contemplados.

## 26. Necesidad de una prueba de inicio a fin

## Resumen final — Llamada 7

Se mostró una versión mucho más completa del sistema: plataforma interna, operaciones,
clientes, facturación con conexión demo a Alegra, motorizados, mapa, muestras, catálogo,
perfiles personalizados y portal del cliente final. A3 validó que la parte interna está
bastante bien, pero remarcó que falta pulir la experiencia del cliente en el chatbot y lograr
una prueba completa de inicio a fin.

Durante la prueba aparecieron varios ajustes importantes: no permitir cambiar el cliente
maestro una vez seleccionado, permitir cambiar dirección y análisis, permitir varias órdenes
para un mismo cliente, corregir reconocimiento de perfiles como prequirúrgico/parasitológico,
validar mejor especie vs raza, y validar médicos con nombre completo y tarjeta profesional.
También surgió el tema de especies grandes.

Como próximos pasos, A3 debe enviar bases actualizadas de clínicas, médicos, tarjetas
profesionales, especies, razas y clientes nuevos. Con esa información, el equipo ajustará el
bot y se programará una nueva prueba completa. También quedó Anarbet como pendiente: si no
responde con API, se evaluará tomar PDFs de resultados desde OneDrive como alternativa.
