## 3. Problema: validación por teléfono
- El bot está pidiendo teléfono después de ingresar nombre de veterinaria.
- También pide teléfono al ingresar un médico.
- Problema detectado: si se inventa un doctor que no está en base de datos y se ingresa un teléfono cualquiera, el bot avanza igual.
- Riesgo: una persona no validada podría avanzar como si fuera cliente o médico registrado.
- Pedido: el bot no debe avanzar solo por recibir un teléfono si el doctor, veterinaria o cliente no están correctamente verificados en base de datos.

## 4. Problema: cliente, médico o clínica no verificados
- Caso probado: el usuario no respondió médico solicitante ni clínica, pero el chat siguió pidiendo mascota, raza y otros datos.
- Problema: se pudo llegar casi hasta programación sin tener cliente, médico ni clínica validados.
- Cambio pedido: si no hay cliente, médico o clínica validada, el bot debe detener el flujo.
- Mensaje esperado: indicar que debe contactarse o dirigirse a la clínica veterinaria para que ellos contacten a A3.

## 5. Problema: Puppy Export / múltiples sedes / teléfono
- Caso probado: Puppy Export, que tiene varias sedes.
- El bot pidió teléfono. Se ingresó un número registrado de Puppy Export.
- Error: el sistema terminó ingresando un cliente completamente diferente al escrito inicialmente.
- Pedido: corregir la lógica para que el teléfono no cambie el cliente original a otro registro sin confirmar.

## 6. Búsqueda por palabra clave
- El bot todavía no está resolviendo bien búsquedas por palabra clave.
- Caso probado: se escribió "doc". Problema: el bot tomó solo una veterinaria en vez de mostrar varias opciones con esa palabra clave.
- Pedido: si hay varias coincidencias, el bot debe mostrar una lista de opciones.
- Ejemplo de comportamiento esperado: si el usuario escribe "mascotas" y hay muchas veterinarias con esa palabra, el bot debería pedir una palabra más específica o mostrar una lista limitada de coincidencias.
- Si hay pocas coincidencias, mostrar opciones numeradas.
- Luego confirmar la opción elegida.

## 12. Explicación inicial de "Crea tu perfil"
- A3 quiere migrar de perfiles fijos hacia "Crea tu perfil".
- La idea es que los descuentos se apliquen por cantidad de pruebas, no por tipo de perfil tradicional.
- Ejemplo de lógica: 2 pruebas → 10 %; 3 → 12 %; 4 → 14 %; 5 → 16 %; y así según una fórmula o variable.
- El descuento se aplicaría sobre el precio base de cada prueba.
- La lógica busca simplificar, sin separar por hematología, minerales, químicas, hormonas, pruebas especiales, etc.
- **A3 quiere que el porcentaje sea editable desde la plataforma.**
- Luciano confirma que pueden pasar una hoja de cálculo con los descuentos y luego se integra a la plataforma para poder modificarlo.

## 13. Sugerencias de pruebas dentro de "Crea tu perfil"
- A3 quiere que el bot pueda sugerir pruebas asociadas a un tipo de perfil.
- Ejemplo: si el médico pregunta por un perfil cardíaco, el bot debería sugerir pruebas relacionadas.
- La idea no es dar diagnóstico ni recomendación médica.
- La idea es usar etiquetas internas basadas en el portafolio ya existente: cardíaco, tiroideo, parasitológico, senior, cachorro, etc.
- El médico debería poder elegir, quitar o agregar pruebas sugeridas.
- Cuantas más pruebas agregue, mayor descuento tendría según la lógica definida.

## 14. Aclaración importante: no es recomendación médica
- A3 aclara que el bot no debe recomendar tratamientos ni resolver casos clínicos.
- No debe funcionar como "mi paciente tiene X síntoma, qué me recomienda".
- Debe limitarse a mostrar pruebas asociadas a perfiles ya existentes en el portafolio.
- Ejemplo: si el usuario pide "perfil toxicológico", el bot agrupa las pruebas que ya existen en los perfiles toxicológicos del portafolio.
- El objetivo es resumir y facilitar la elección, no hacer medicina.

## 15. Debate: alcance nuevo vs evolución del desarrollo
- Luciano advierte que esta lógica puede alargar el desarrollo, porque requiere asociar pruebas, perfiles, etiquetas y sugerencias en una estructura nueva.
- A3 considera que no es un desarrollo nuevo, sino una evolución de "Crea tu perfil".
- A3 argumenta que la información ya está en la lista de precios y que se trata de reorganizarla.
- El punto queda abierto para que A3 lo envíe explicado y el equipo pueda evaluar lógica, tiempos e implementación.

## 16. Información que A3 debe preparar sobre perfiles
- A3 debe enviar la lógica de "Crea tu perfil" más visual y ordenada (hoja, dibujo, esquema o documento).
- Debe mostrar cómo imaginan la interacción del bot en esa parte.
- Debe incluir qué pruebas se asocian a cada perfil o etiqueta.
- Debe incluir cómo se aplican los descuentos por cantidad.
- Luciano pide esa información para evaluar cuánto tiempo llevaría y cómo desarrollarlo.

## 17. Simplificación de perfiles para futuras integraciones
- A3 quiere dejar de manejar perfiles como unidad rígida de producto.
- Objetivo: trabajar más con pruebas individuales asociadas a etiquetas y descuentos por cantidad.
- Motivo: facilitar reportes, inventarios, reactivos, integración con Alegra y Anarbet.
- Ejemplo: en vez de contar 10 hemogramas sueltos más varios perfiles cachorro que contienen hemogramas, se busca saber directamente cuántos hemogramas reales se hicieron.

## 18. Analogía usada para entender la lógica
- Se usa una analogía de pizza para explicar perfiles y pruebas.
- Un perfil sería como una pizza base con ingredientes sugeridos.
- El cliente puede quitar o agregar ingredientes/pruebas.
- Las mismas pruebas pueden aplicar a varios perfiles/etiquetas.

## Resumen final — Llamada 6

El foco principal fue el testeo real del agente conversacional. A3 detectó que el bot todavía
permite avanzar con datos no verificados, especialmente cuando pide teléfono, y que la búsqueda
por palabra clave aún no funciona como necesitan: si hay varias coincidencias, debe mostrar
opciones y no elegir una al azar. También se habló de mejorar el lenguaje para que sea más
natural y personalizado.

Además, se profundizó en la lógica de "Crea tu perfil". A3 quiere simplificar los perfiles
actuales y pasar a una lógica basada en pruebas individuales, etiquetas y descuentos por
cantidad. El bot debería poder sugerir pruebas asociadas a perfiles existentes del portafolio,
como cardíaco, toxicológico o cachorro, pero sin hacer recomendaciones médicas. Este punto
quedó como una evolución importante que A3 debe enviar más ordenada en un documento o esquema.
