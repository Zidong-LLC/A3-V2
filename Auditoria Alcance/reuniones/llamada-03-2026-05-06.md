## 3. Cliente nuevo: mensaje de derivación
- **Problema detectado:** cuando un usuario decía "soy cliente nuevo y quiero tomar servicios", el bot respondía "claro, con gusto", pero no dejaba claro que lo iba a atender una persona.
- **Cambio pedido:** el bot debe decir explícitamente que asignará un asesor/agente humano.
- Mensaje sugerido: *"Permíteme un momento, te asignaremos un asesor."* o *"Te comunicaremos con un asesor en breve."*
- Objetivo: que el cliente nuevo entienda que no seguirá hablando solo con la IA.
- **Riesgo señalado:** si todos reciben solo "claro, con gusto", A3 podría perder clientes nuevos porque no queda claro qué pasa después.

## 4. Registro / validación de cliente existente
- **Problema detectado:** el bot pregunta NIT o nombre de veterinaria, pero luego vuelve a pedir NIT aunque el usuario ya haya dado el nombre.
- Pedido: eliminar el loop o doble validación innecesaria.
- **Regla definida:** si el cliente ya fue ubicado por nombre o por NIT, no pedir nuevamente el otro dato salvo ambigüedad.
- Propuesta de respuesta: *"Listo, ya te identifiqué. Estos son tus datos…"* y pedir confirmación, en lugar de volver a pedir NIT.
- **Consideración importante:** algunos doctores mayores se molestan si el sistema les pregunta lo mismo varias veces. El cliente pide simplificar al máximo la experiencia.

## 5. Clientes con nombres similares o múltiples sedes
- Problema: hay veterinarias con nombres parecidos o iguales. Ejemplo: Pro Animal puede aparecer con varias veterinarias que no son del mismo dueño.
- Problema adicional: hay clientes con varias sedes bajo el mismo NIT o nombre comercial. Ejemplo: Pupisport maneja Hayuelos, Quinta Paredes, Niza y Centro Mayor.
- Cambio pedido: si el nombre coincide con varias opciones, mostrar una lista para que el cliente seleccione la clínica/sucursal correcta.
- Agregar confirmación final: *"¿Estás seguro de programar tu ruta en la clínica veterinaria X sede Y?"*
- **Regla dinámica:**
  - una sola sede → mostrar datos y pedir confirmación;
  - varias sedes → mostrar opciones;
  - nombres similares → mostrar lista de posibles coincidencias;
  - persona natural con nombre comercial → mostrar el registro correspondiente para confirmar.

## 6. Flujo conversacional dinámico, no lineal
- **Pedido de A3: el flujo no debe ser un único camino rígido.** Debe ramificarse según lo que aparezca en la base de datos.
- Casos a contemplar: cliente encontrado por NIT; por nombre; con varias sedes; nombres similares; persona natural con nombre comercial; cliente nuevo que no dice explícitamente "soy cliente nuevo".
- Luciano confirma que se pueden hacer ramificaciones: mostrar opciones numeradas y luego confirmar la seleccionada.

## 9. Orden de servicio dentro del chat
- **La orden de servicio no debe quedar como formulario externo de Google.**
- El bot debe pedir los datos paso a paso dentro de la conversación.
- Campos mencionados: fecha; médico solicitante; nombre del paciente; especie; raza; sexo; análisis/exámenes requeridos.
- Pendiente: definir en qué punto exacto del flujo se solicita la orden: antes o después del resumen de análisis/pago.

## 10. Catálogo, perfiles y búsqueda por palabras clave
- Al diligenciar exámenes, el usuario debe poder consultar catálogo o usar palabras clave.
- Ejemplo: "prequirúrgico" → opciones relacionadas. "tiroides" → perfiles tiroideos disponibles.
- Si el usuario elige un perfil específico, debe mostrar qué pruebas contiene. Ejemplo: perfil 601 → T3 total y T4 total.
- Esa información ya está en el portafolio, en el área de perfiles.

## 11. Perfiles personalizados

- El sistema debe mostrar resumen y precio estimado.
- A3 valida que esa lógica va en la dirección correcta.
- **Falta aplicar descuento.**
- **Falta guardar el perfil creado por cliente/veterinaria para reutilizarlo después.**

## Resumen final — Llamada 3

Se revisaron los ajustes realizados sobre el chatbot y se detectaron mejoras importantes para
hacerlo más simple y usable. El principal cambio fue evitar que el bot repita preguntas,
especialmente NIT/nombre, y convertir la validación de cliente en un flujo dinámico que contemple
nombres similares, varias sedes y personas naturales con nombre comercial. También se ajustó el
mensaje para clientes nuevos, dejando claro que serán atendidos por un asesor humano. Se validó la
lógica de perfiles personalizados, pero quedaron pendientes descuentos, guardado de perfiles
favoritos y reutilización por clínica. Además, A3 pidió que la orden de servicio se diligencie
dentro del chat y no como formulario externo. Finalmente, se mostró una demo inicial de la
plataforma, aclarando que se construye desde cero.
